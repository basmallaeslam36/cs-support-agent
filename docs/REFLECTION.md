Design decision. For the loyalty discount tool I used the AgentCore Code Interpreter instead of letting the model do the math. The rules are exact: 100 points equal $1, redemption is in steps of 500, points cover at most half the order, and the tier discount applies after points. A language model can slip on arithmetic, but code in a sandbox always gives the same answer. For a Gold member with 4,250 points and a $150 order, the agent returned 4,000 points redeemed, a $99.00 total, and 250 points left, which matched the catalog's rules. I also added a fallback that applies only the tier discount if the interpreter is unavailable, so the tool still returns an answer.

Challenge. Deployment was the hardest part. The default agentcore deploy builds the container in CodeBuild, and in the lab account the builds were stopped within seconds, with no logs to explain it. I switched to a local Docker build, but the toolkit said no container engine was found even though Docker was running. The generated config file had container_runtime: none, and changing it to docker fixed that. The agent then deployed but crashed on startup. The CloudWatch logs showed the command-line test function running instead of the server, because I had left main() active instead of app.run(). After fixing the last lines of main.py and redeploying, all six tests passed.

Production consideration. Security needs work before real customers use this. The execution role the toolkit created could not query the Knowledge Base or use the browser, so I added narrowly scoped inline IAM policies, for example allowing only bedrock:Retrieve on my knowledge base. In production I would keep permissions that tight. I would also replace the Gateway's "no authorization" setting, which was only acceptable in this sandbox, with IAM or JWT authentication, and delete leftover resources such as the ECR repository and the CodeBuild project to avoid unexpected cost.
